# 手机端 DOM＋Canvas 重构设计

日期：2026-07-30  
状态：交互与架构方向已由用户确认，待书面规格审核

## 1. 目标

把现有日本向 Water Sort H5 从 Phaser 重构为原生 DOM＋Canvas 2D
实现，优先改善 TikTok 流量进入后的手机体验：

- 首次打开更快；
- 触摸立即反馈，不再产生“点了没反应”的感觉；
- 倒水动画流畅且短；
- 不同尺寸、刘海屏和横竖屏下都能自然布局；
- 在低性能手机和 TikTok 内置浏览器中自动降低画质以保持流畅；
- 保留日式清爽、可爱玻璃、2.5D 渐变质感。

本次重构服务于广告互动率测试。用户不需要登录，打开页面后直接进入当前关卡。

## 2. 保留范围

以下现有能力保持不变：

- 日文 UI；
- 8 个现有关卡及 Water Sort 规则；
- 选择瓶子、合法倒水、无效操作、撤销、重开；
- 声音开关与 Web Audio 短音效；
- 通关、手数、用时、下一关和重玩；
- `water-sort-progress` 的现有 `localStorage` 数据格式；
- 分析和广告的安全空适配器；
- GitHub Pages 静态部署方式。

不增加以下内容：

- 用户账号、服务端 API、排行榜或支付；
- 实际广告 SDK；
- 实时 3D 引擎；
- 外部字体、大图、视频或远程美术资源；
- 新关卡、新玩法或提示系统。

## 3. 技术方案

移除 Phaser 运行时，保留 Vite、TypeScript 和 Vitest。页面分成 DOM 外壳与单个
Canvas 游戏区域。

### DOM 外壳

DOM 负责：

- 顶部撤销、关卡、声音按钮；
- 标题和首次操作提示；
- Canvas 容器；
- 底部重开按钮；
- 通关面板；
- 刘海屏安全区、页面尺寸和横竖屏布局；
- 无障碍名称、按钮禁用状态和键盘操作。

### Canvas 游戏区域

单个 Canvas 负责：

- 背景的轻量装饰；
- 所有玻璃瓶、液体、选中状态和合法目标光效；
- 瓶子移动、倾斜、液流和着水波纹；
- 无效操作摇动；
- 通关纸屑。

Canvas 静止时不运行持续动画循环。只有状态变化、页面尺寸变化或动画播放时才
请求下一帧。

### 模块边界

- `GameApp`：组合状态、输入、动画、DOM 和 Canvas，不包含规则细节。
- `ResponsiveLayout`：根据可用宽高、安全区和瓶子数量生成布局。
- `CanvasRenderer`：按当前状态绘制场景，不修改游戏状态。
- `RenderScheduler`：管理脏帧和动画帧，保证空闲时没有持续
  `requestAnimationFrame`。
- `PointerController`：命中检测、指针捕获、移动容差、取消和单次排队。
- `PourAnimator`：生成 0～1 的时间进度和瓶子临时姿态，不提交规则状态。
- `AdaptiveQuality`：选择渲染倍率、发光和纸屑等级，并只允许向下调整。
- 现有 `domain`、`session`、`levels`、`audio`、`adapters` 模块继续复用。

## 4. 自适应布局

首要目标为宽度 320～480 CSS 像素的竖屏手机。页面使用 `100dvh` 和
`env(safe-area-inset-*)`，不使用固定 540×960 页面尺寸。

页面由上到下分成：

1. 安全区与顶部控制栏；
2. 标题和一次性操作提示；
3. 可伸缩的游戏棋盘；
4. 底部重开控制与安全区。

布局规则：

- 6 本瓶子使用 3 列两行，7～8 本使用 4 列两行；
- 瓶子宽度、行距和列距根据 Canvas 的实际 CSS 尺寸计算；
- 瓶子视觉宽度最小 44 CSS 像素；
- 触摸热区最小 56×72 CSS 像素，并允许相邻热区之间保留至少 4 像素间隔；
- 棋盘优先占满剩余高度，不让底部控制超出可视区域；
- 竖屏较矮时先压缩标题间距，再等比例缩小瓶子；
- 横屏时保持居中的竖向棋盘，控制栏分布在棋盘两侧或上下边缘，不强制用户旋转；
- `resize`、`orientationchange` 和可视视口变化统一触发布局重算；
- 页面尺寸变化期间取消旧动画姿态，将画面同步到确定的游戏状态。

## 5. 清晰度与自适应画质

Canvas 的 CSS 尺寸与内部像素尺寸分离。初始渲染倍率为：

`min(devicePixelRatio, 2)`

这样可改善当前固定 540×960 画布在 Retina 和高分屏手机上的发虚，同时避免
直接使用 3 倍或 4 倍分辨率造成过高填充压力。

画质分为三级：

- `high`：倍率最高 2，完整玻璃高光、柔光和 32 个通关纸屑；
- `balanced`：倍率最高 1.5，简化外发光和 20 个纸屑；
- `low`：倍率为 1，取消外发光，保留玻璃轮廓、液体渐变和 12 个纸屑。

第一次倒水动画期间采样帧间隔。若滚动平均帧间隔超过 20 毫秒，降至
`balanced`；若超过 26 毫秒，降至 `low`。同一会话不自动升级，避免画质来回
跳变。降级只影响装饰，不改变瓶子位置、命中范围、颜色和玩法。

不支持 `OffscreenCanvas` 时使用隐藏的普通 Canvas 作为缓存，不视为错误。

## 6. 绘制策略

瓶子不再对应多个长期存在的 Graphics 和 Geometry Mask 对象。

- 玻璃外壳、高光和阴影按尺寸与画质等级缓存为离屏位图；
- 液体按颜色、层数和尺寸缓存为轻量位图；
- 状态未变化的瓶子复用缓存；
- 普通选择和取消只标记选择前后的瓶子为脏；
- 合法倒水只更新来源瓶和目标瓶；
- 动画帧仍重绘单个 Canvas，但不销毁和重建图形对象；
- 动画之外仅在状态、尺寸或 DOM 覆盖层变化时绘制一次；
- 纸屑和波纹有明确结束时间，结束后停止调度帧。

绘制顺序固定为背景、瓶子阴影、液体、玻璃、状态光效、动画临时层和纸屑。
Canvas 绘制异常时终止当前动画、提交确定的最终盘面并恢复输入。

## 7. 触摸与操作手感

所有交互使用 Pointer Events，同时兼容触摸、鼠标和触控笔。

### 普通点击

1. `pointerdown` 命中瓶子后立即显示按压高亮，并捕获该指针；
2. 指针移动不超过 12 CSS 像素且在 `pointerup` 时仍命中同一瓶子，确认点击；
3. 超出容差、`pointercancel` 或窗口失焦时取消，不执行误操作；
4. 多指操作时只接受第一个拥有者，其他指针在释放前保持拒绝状态；
5. DOM 按钮与 Canvas 棋盘拥有互斥的指针所有权。

### 动画期间

合法倒水开始后规则状态保持锁定，但输入控制器最多保存一次后续瓶子点击。
动画完成并提交盘面后，排队点击立即按新盘面重新验证。排队期间的更多点击被
忽略，撤销、重开和声音按钮不进入队列。

这保证快速玩家不会因为 0.7～0.9 秒动画完全丢失下一次操作，也不会因为多次
连点造成状态错乱。

### 动画时长

倒水总时长必须在 700～900 毫秒内：

- 抬起：100 毫秒；
- 移动：150 毫秒；
- 倾斜：100 毫秒；
- 倒水：250～400 毫秒，随液体数量增加；
- 返回：120 毫秒；
- 波纹与返回并行，不单独延长输入锁。

无效操作摇动为 160 毫秒。选择高亮在下一绘制帧出现。

## 8. 状态与数据流

`GameState` 仍是唯一的规则状态，Canvas 动画姿态不写入 `GameState`。

合法倒水流程：

1. `PointerController` 产生确认点击；
2. 现有 reducer 返回选择、无效或倒水效果；
3. 选择只更新所需瓶子的显示状态；
4. 合法倒水把规则状态标记为待提交；
5. `PourAnimator` 生成临时瓶子位置、角度、液流和液面进度；
6. 动画结束后调用现有 `commitPendingMove`；
7. 渲染器同步来源瓶和目标瓶；
8. 进行通关判断；
9. 未通关时重新验证并执行一次排队点击。

动画失败、页面隐藏或尺寸变化时，跳过剩余临时姿态，提交确定的待处理移动并
恢复可操作状态。任何时候都不允许 Canvas 显示状态永久领先或落后于
`GameState`。

## 9. 加载与资源预算

- 删除 Phaser 依赖和相关打包代码；
- 不新增运行时第三方依赖；
- production 入口 JavaScript 的 gzip 大小目标小于 100 KB；
- CSS 的 gzip 大小目标小于 15 KB；
- HTML 先显示轻量背景与日文加载提示，脚本初始化后立即替换为游戏；
- 不等待音频、图片、字体或网络 API 才开始；
- GitHub Pages 必须继续使用相对资源路径；
- 首次脚本执行失败时显示日文重试按钮，不显示空白屏。

## 10. 视觉表现

视觉方向仍为轻量日系 2.5D，不是真实时 3D：

- 米白、淡紫、淡蓝背景；
- 圆润透明玻璃、内侧反光和柔和阴影；
- 液体使用上下渐变和椭圆液面；
- 选择时瓶子上浮、轻微倾斜并出现薄光环；
- 合法目标只使用低强度薄荷色轮廓；
- 倒水时显示短液流和着水波纹；
- 低画质模式仍保留轮廓、渐变和液面，不能退化成纯色矩形；
- 日文 DOM 文案继续使用系统字体，避免字体下载。

## 11. 错误处理

- Canvas 2D 不可用：显示日文错误提示和重试按钮；
- 动画异常：提交最终盘面、清空队列并解锁输入；
- 页面隐藏：暂停计时和动画；恢复后同步到确定状态；
- 尺寸变化：取消临时动画并重新布局；
- 音频不可用：自动静音，游戏继续；
- `localStorage` 不可用或数据损坏：使用默认进度，游戏继续；
- 广告或分析适配器异常：吞掉异常，不阻塞玩法；
- 低帧率：仅降低装饰画质，不改变规则或触摸热区。

## 12. 迁移策略

重构期间保留现有规则、关卡、进度、音频和适配器测试。Phaser 相关的
`GameScene`、`TubeView`、`PourAnimator` 和 `UIButton` 在替代模块测试通过后
一次性移除，避免 production 同时打包两个渲染器。

现有 `water-sort-progress` 的版本保持为 `1`，已部署用户的关卡进度、最佳手数和
声音设置无需迁移。
